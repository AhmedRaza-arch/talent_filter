# 10.1 UI/UX: Base Layout

## Understanding the Layout Foundation

In this section, we'll explore the base layout structure of the Talent Filter application. A well-organized layout is essential for creating a consistent user experience across the application.

## Template Structure

The application uses a template inheritance system to maintain consistency across pages:

### Template Directory Structure

```
templates/
├── base.html          # Original base template (not used)
├── base1.html         # Main base template with navigation
├── auth/
│   ├── login.html
│   ├── job_seeker_signup.html
│   └── recruiter_signup.html
├── components/
│   ├── footer.html
│   ├── header.html
│   └── notification_dropdown.html
```

### Main Base Template (base1.html)

The `base1.html` template provides the foundation for all pages in the application:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>{% block title %}Talent Filter{% endblock %}</title>

    <!-- Bulma CSS -->
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bulma@0.9.4/css/bulma.min.css">

    <!-- Font Awesome -->
    <link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/css/all.min.css">

    <!-- Google Fonts -->
    <link rel="preconnect" href="https://fonts.googleapis.com">
    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
    <link href="https://fonts.googleapis.com/css2?family=Cabin:wght@400;500;600;700&family=Dancing+Script:wght@400;500;600;700&display=swap" rel="stylesheet">

    <!-- Custom CSS -->
    <link rel="stylesheet" href="{% static 'css/styles.css' %}">
    <link rel="stylesheet" href="{% static 'css/theme.css' %}">

    {% block extra_css %}{% endblock %}
</head>
<body>
    <!-- Header -->
    {% include 'components/header.html' %}

    <!-- Main Content -->
    <main class="main-content">
        {% if messages %}
            <div class="container mt-3">
                {% for message in messages %}
                    <div class="notification is-{{ message.tags }} is-light">
                        <button class="delete"></button>
                        {{ message }}
                    </div>
                {% endfor %}
            </div>
        {% endif %}

        {% block content %}{% endblock %}
    </main>

    <!-- Footer -->
    {% include 'components/footer.html' %}

    <!-- jQuery -->
    <script src="https://code.jquery.com/jquery-3.6.0.min.js"></script>

    <!-- Custom JavaScript -->
    <script src="{% static 'js/main.js' %}"></script>

    {% block extra_js %}{% endblock %}
</body>
</html>
```

### Key Layout Components

The base template includes several key components:

1. **Head Section**: Contains meta tags, title, and CSS links
2. **Header**: Contains the navigation bar (included from a separate file)
3. **Main Content**: Contains the page-specific content (defined in child templates)
4. **Footer**: Contains links and copyright information (included from a separate file)
5. **JavaScript**: Includes jQuery and custom JavaScript files

### Template Blocks

The base template defines several blocks that child templates can override:

- `{% block title %}`: Page title
- `{% block extra_css %}`: Additional CSS files
- `{% block content %}`: Main page content
- `{% block extra_js %}`: Additional JavaScript files

### Child Template Example

Here's an example of how a child template extends the base template:

```html
{% extends 'base1.html' %}

{% block title %}Dashboard - Talent Filter{% endblock %}

{% block content %}
<div class="section">
    <div class="container">
        <h1 class="title">Dashboard</h1>
        <!-- Dashboard content goes here -->
    </div>
</div>
{% endblock %}
```

## Responsive Design

The application is designed to be responsive, adapting to different screen sizes:

### Mobile-First Approach

The layout is designed to work on small screens first, then enhanced for larger screens.

### Responsive Breakpoints

Bulma provides responsive breakpoints that the application uses:

- Mobile: < 768px
- Tablet: 768px - 1023px
- Desktop: 1024px - 1215px
- Widescreen: 1216px - 1407px
- Fullhd: ≥ 1408px

### Responsive Navigation

The navigation bar collapses to a hamburger menu on small screens:

```javascript
// Toggle mobile navigation
document.addEventListener('DOMContentLoaded', () => {
    // Get all "navbar-burger" elements
    const $navbarBurgers = Array.prototype.slice.call(document.querySelectorAll('.navbar-burger'), 0);

    // Check if there are any navbar burgers
    if ($navbarBurgers.length > 0) {
        // Add a click event on each of them
        $navbarBurgers.forEach(el => {
            el.addEventListener('click', () => {
                // Get the target from the "data-target" attribute
                const target = el.dataset.target;
                const $target = document.getElementById(target);

                // Toggle the "is-active" class on both the "navbar-burger" and the "navbar-menu"
                el.classList.toggle('is-active');
                $target.classList.toggle('is-active');
            });
        });
    }
});
```

## Layout Customization

The application includes several custom layout styles:

### Full-Height Layout

```css
html, body {
    min-height: 100vh;
}

body {
    display: flex;
    flex-direction: column;
}

.main-content {
    flex: 1;
    padding-top: 3.25rem; /* Height of the fixed navbar */
}
```

This ensures that the footer sticks to the bottom of the page, even when there's not enough content to fill the viewport.

### Fixed Navigation

```css
.navbar {
    position: fixed;
    top: 0;
    width: 100%;
}
```

The navigation bar is fixed to the top of the page, so it's always visible when scrolling.
